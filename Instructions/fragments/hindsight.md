## Useful feedback

When `hindsight.submit_feedback` is available, use it at the final handoff only
for observed, actionable friction or a reusable improvement in instructions,
skills, code, collaboration, or tooling. Include a concise finding, its impact,
and a concrete next step. Skip empty feedback, generic praise, and invented
problems. Feedback failure must not block the requested task.

Use a fresh request ID for each submission. Retry only an identical payload
with the same ID; do not loop. Add a bounded task, repository, source/client,
and outcome when useful. Never include credentials, personal data, transcripts,
or private provider instructions. Feedback is attributable to the ingestion
key owner. Keep the existing approval settings and respect denied tool calls.
